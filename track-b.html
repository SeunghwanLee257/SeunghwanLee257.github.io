B · B2B · Agent Security

FHE16 Agent Gate: controlling what an AI agent is allowed to do

AI agents now execute payments, refunds, data exports, and risk actions directly. Agent Gate sits between the agent and its tools as an execution-security layer that enforces pre-approved rules and returns only the needed decision without exposing sensitive inputs.

Problem

When data becomes an instruction

When an agent reads external documents, email, or web content, embedded malicious instructions can chain allowed tool calls into data exfiltration or wrong actions. In the NIST CAISI 2026 red-team, all 13 targeted frontier models had at least one successful attack.

How it works

A three-layer execution boundary

① A deterministic policy checks allowed tools, identity, amount, recipient, purpose, and evidence; ② protected amounts, thresholds, and risk scores are evaluated on ciphertext with FHE16; ③ a threshold-approval step keeps any single party from decrypting alone. The output is ALLOW / REVIEW / DENY with a reason code.

First market

High-risk actions in finance

The first targets are payment, refund, PII export, and limit/risk actions, where an error costs more than a wrong answer. In Korea, 169 generative-AI innovative financial services have been designated and 45 launched — read as an adoption signal, not a customer count.

Status

What works now vs. the pilot scope

A deterministic policy gate works today (9/9 baseline tests). The on-ciphertext decision and threshold release, plus a Naver Cloud CLOVA Studio Skill connection with domestic-region performance and cost measurement, are the pilot scope. This is an integration in progress that links a policy baseline with cryptographic research assets, not a finished product.
