FHE16 apps split into server-side FHE (the server computes on ciphertext) and browser-side FHE (the browser computes on ciphertext and sends only the result to the server). This page is a browser-side private policy demo, but location search and ad/offer matching fit server-side FHE better.FHE16 앱은 서버가 암호문을 계산하는 server-side FHE와 브라우저가 암호문을 계산한 뒤 결과를 서버에 보내는 browser-side FHE로 나뉩니다. 이 페이지는 browser-side private policy demo지만, 위치 검색과 광고/offer matching은 server-side FHE가 더 맞습니다.

FHE16 app mode classificationFHE16 앱 모드 분류

The product story becomes clearest when you categorize apps by where computation happens. If the server holds the catalog/model/ranking, use server-side FHE. If the browser evaluates policy and sends only the result, use browser-side FHE.앱을 계산 위치로 나눠야 제품 이야기가 선명해집니다. 서버가 catalog/model/ranking을 갖고 있으면 server-side FHE, 사용자의 브라우저에서 policy를 평가하고 결과만 서버가 받아야 하면 browser-side FHE입니다.

Compute
Server, GPU/FPGA, cloud worker, or FHE coprocessor computes on ciphertext.서버, GPU/FPGA, cloud worker, FHE coprocessor가 암호문을 계산합니다.

Browser-side FHE

Compute
Browser worker combines encrypted policy and user predicate.브라우저 worker가 encrypted policy와 user predicate를 조합합니다.
Apps
Finance/insurance prequalification, clinical trial/HR self-check, consent-gated eligibility, endpoint local rule evaluation.금융/보험 사전심사, 임상시험/HR self-check, consent-gated eligibility, endpoint local rule evaluation.
Why
Server receives no raw user data, browser never sees server thresholds in plaintext, server receives only enc_result for decrypt/sign.서버는 raw user data를 받지 않고, 브라우저는 서버 threshold를 평문으로 보지 않으며, 서버는 enc_result만 받아 decrypt/sign합니다.

Outsourced FHE / MPC hybrid

Compute

Honest sellability verdict솔직한 sellability 판정

Positioning this as a general-purpose browser FHE platform will not sell. The winning positioning is "private decisioning SDK" with computation limited to small predicate circuits.이건 범용 브라우저 FHE 플랫폼으로 팔면 안 팔립니다. 팔리는 포장은 "private decisioning SDK"이고, 계산은 작은 predicate circuit으로 제한해야 합니다.

Sellable conditions팔리는 조건

  • The customer's actual revenue/approval is blocked due to data minimization requirements or model IP exposure고객이 데이터 최소수집이나 모델 IP 노출 때문에 실제 매출/심사가 막혀 있음
  • Result is small: yes/no, risk bucket, limit bucket결과가 yes/no, risk bucket, limit bucket처럼 작음
  • Policy fits within 10–50 predicates정책이 10-50개 predicate 안에 들어옴
  • Inputs can be received as signed claims or telemetry bits from issuer/API/device입력은 issuer/API/device가 만든 signed claim 또는 telemetry bit로 받을 수 있음

Unsellable conditions안 팔리는 조건

  • Trying to run 32-bit multiplication, division, or full model inference in browser32-bit 곱셈, 나눗셈, full model inference를 브라우저에서 돌리려 함
  • Requiring Level 3 PFE (server must fully hide the whole circuit) as MVP서버가 회로 전체를 완전히 숨겨야 하는 Level 3 PFE를 MVP로 요구함
  • Architecture requires trusting user-entered values directly사용자가 직접 입력한 값을 믿어야 하는 구조임
  • Approaching as a free PoC or research demo only무료 PoC 또는 연구 데모로만 접근함

Why it sells technically기술적으로 팔리는 이유

Plain local JS exposes server rules. The FHE16 server-key structure treats both user input and server thresholds as ciphertext while keeping the secret key and plaintext policy on the server. Full circuit hiding is deferred to 2PC/PFE phase 2.단순 local JS는 서버 rule을 노출합니다. FHE16 server-key 구조는 사용자 입력과 서버 threshold를 모두 암호문으로 다루면서, 서버가 secret key와 평문 policy를 계속 보관하게 해줍니다. full circuit hiding은 2PC/PFE phase 2로 미룹니다.

Technical Demo

The current WASM runtime demonstrates that encrypted predicate bit combinations run stably in the browser. In the production product the server holds the SK, plaintext thresholds, and policy compiler, and deploys only the encrypted policy blob and evaluation key to the browser. 2PC/PFE is added as phase 2 when circuit topology also needs to be hidden.현재 WASM runtime은 encrypted predicate bit 조합이 브라우저에서 안정적으로 실행되는지를 시연합니다. production 제품은 서버가 SK, 평문 threshold, policy compiler를 보관하고 브라우저에는 encrypted policy blob과 evaluation key만 배포합니다. 2PC/PFE는 circuit topology까지 숨겨야 할 때 phase 2로 붙입니다.
