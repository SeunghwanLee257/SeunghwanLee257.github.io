## 막힌 것 — 비교 결과와 일반 정수를 섞으면 중단

```
LT(a, 0) 단독                    → 정상
LT 결과 + 일반 정수              → Aborted()
LT 결과 × 일반 정수              → Aborted()
LT 결과 + LT 결과                → 정상
```

비교 연산은 **다른 종류의 암호문**을 만든다. 폭 문제가 아니다. `a<b` 를 `sub(a,b)` 의 부호 판정으로 바꿔도 같은 결과가 나온다.

### 이것이 막는 것

상태 합류 회로가 조건을 값과 곱한다.

```
φ(c, t, e) = e + c·(t − e)
```

`c` 가 비교 결과이므로 곱셈에서 중단된다. 그래서 **분기와 삼항연산자가 암호문에서 동작하지 않는다.** 산술만 쓰는 프로그램은 정상이다.

### 남은 길

1. 비교 없이 조건을 만든다 — `(b−a) >> 31` 로 부호 비트를 뽑는다. 확인 중
2. 엔진 쪽에서 비교 결과를 일반 정수 도메인으로 되돌리는 연산을 노출한다
3. 특수형만 쓴다 — `c ? a : b` 에서 조건이 `a>b` 이면 `max(a,b)` 로 대체

### 재현

```
cd demo && python3 coiserve.py 8733 .
```

격리 헤더(`Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp`)가 없으면 pthreads 빌드가 로드되지 않는다.


## 2026-09-14 추가 실측

### 비교 연산은 다른 도메인이다

```
LT(a,0) 단독            정상
LT 결과 + 일반 정수      Aborted()
LT 결과 × 일반 정수      Aborted()
LT 결과 + LT 결과        정상
```

폭 문제가 아니다. `a<b` 를 `sub(a,b)` 의 부호 판정으로 바꿔도 같다. 비교 연산이 **일반 정수와 섞이지 않는 암호문**을 만든다.

상태 합류 회로가 조건을 값과 곱하므로, 조건은 정수 도메인에 남아야 한다.

### 논리곱은 비트 단위가 아니다

```
m1 = 0 − c  →  255     정확
20 & 255    →  0       기대 20
```

`FHE16_AND` 는 단일 비트 게이트다. 원핫 마스킹 `(t & m1) ^ (e & m0)` 은 이 빌드에서 성립하지 않는다. 산술 `e + c·(t−e)` 를 기본값으로 둔다.

### 산술만으로 비교 만들기 — 정확하지만 비싸다

```
nz(x)    = min(1, abs(x))                 x ≠ 0 이면 1
eq(a,b)  = 1 − nz(a−b)
ge(a,b)  = 1 − nz(max(a,b) − a)
le(a,b)  = 1 − nz(max(a,b) − b)
gt(a,b)  = ge(a,b) − eq(a,b)
```

평문 백엔드에서 전부 정확하다. 암호문에서도 각 단계를 따로 부르면 맞다.

**비용이 문제다.** `gt` 하나가 max·sub·abs·min·sub 를 두 벌 쓴다. 네이티브 `FHE16_GT` 는 1연산인데 10연산이 된다. 브라우저 단일 스레드에서 분 단위가 나온다.

### 해결 — FHE16_SELECT 노출 (2026-09-14)

`FHE16_SELECT` 는 이미 구현돼 있었다. `src/soAPI/soAPI.cpp:3867` 이고 나눗셈 내부에서도 쓰인다. **내보내기 목록에만 빠져 있었다.**

`FHE16_WASM_LIB/exported_functions.txt` 에 두 줄을 넣고 다시 빌드했다.

```
_FHE16_SELECT
_FHE16_FSELECT
```

172줄에서 174줄이 되고, 내보내기가 177종에서 179종이 됐다.

비교 결과를 `FHE16_SELECT` 에 바로 넣으면 정상 동작한다. 그 결과를 다시 산술에 넣어도 된다. 중첩도 된다.

```
GT(9,4)                    → 1
SELECT(gt, 20, 7)          → 20
SELECT(gt,20,7) + 5        → 25
SELECT(gt,20,7) * 2        → 40
중첩 SELECT                → 정확
```

### 빌드 기록

여섯 공개 빌드 전부 다시 만들었다. 전부 `FHE16_RELEASE_MODE=UNSAFE` 다 — 공개 WASM 정책대로다(CMakeLists.txt 499~515행).

| 빌드 | AVXTYPE | pthreads | 비고 |
|---|---|---|---|
| avx6 | 6 | ON | |
| avx6st | 6 | OFF | |
| avx7 | 7 | ON | relaxed SIMD |
| avx8 | 8 | OFF | 순수 JS |
| avx9 | 9 | ON | SIMD 없음 |
| avx9st | 9 | OFF | |

**avx8·avx9·avx9st 는 `AVXTYPE` 이 캐시에 0 으로 남아 있어 재설정이 필요했다.** CMakeLists 가 `AVXTYPE=8/9` 를 스칼라 0 으로 낮춰 쓰고 그 값이 캐시에 기록되기 때문이다. 다시 빌드할 때는 `-DAVXTYPE=9` 를 명시한다.

`FHE16_WASM_LIB/minify_wasm.sh` 가 wasm-opt 와 terser 를 돌린다. 원본을 `.orig` 로 보존하고, 내보내기 이름·개수가 같은지 검증한 뒤에만 바꾼다.

## 2026-09-17 컴파일러 쪽 처리

비교 결과(조건 도메인)를 값으로 쓰던 곳을 전부 정수화했다.

- 백엔드가 `conditionIsInteger` 를 알린다. 네이티브 비교(FHE16_SELECT 빌드)면 `false`.
- 컴파일러는 조건을 산술 피연산자·삼항의 값·내장 함수 인자·반환값·`!` 에 쓰기 전에
  `select(c, 1, 0)` 으로 정수 0/1 을 만든다. `φ(c,1,0)=c` 같은 지름길은 정수 도메인에서만 쓴다.
- 조건은 1비트 폭으로 표시되므로 값으로 쓸 때 함수 기본 폭으로 넓힌다. 그 전에는
  평문 백엔드도 `(a<b)*5` 를 1비트로 접어 1 을 냈다.
- 확인: match(8821,8830,30)=1, match(8821,8821,30)=2, `(a<b)*5+(a==b)`=5 — 암호문·평문 일치.
- 컴파일러는 메인스레드에서 동기 호출하므로 단일스레드 빌드(avx6st)를 명시해 로드한다.
  pthread 빌드는 메인스레드를 막으면 워커가 중단된다.
